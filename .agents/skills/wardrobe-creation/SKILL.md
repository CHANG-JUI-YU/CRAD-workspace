# Wardrobe Creation

## Template contract

Bound kind: `wardrobe`. 先讀取 `workspace_template_context` 的衣櫃合約與既有內容，再以 `workspace_template_submit` 提交完整 Markdown。持久化與發布由工作區處理。

## Purpose

建立一份同時適用於珠璣與調色盤的正式角色衣櫃。衣櫃是角色內容的一部分，不是 appearance 的備註，也不是只供 Agent 參考的摘要。

## Inputs

- 已確認的 Blueprint 角色方向。
- 珠璣或調色盤的既有角色模組。
- 角色性格、生活方式、職業、經濟狀況與居住條件。
- 氣候、季節、世界設定與已接受事實。
- 既有衣櫃內容與使用者提出的自然語言修改。

## Content rules

- 以 `# 角色的衣櫃` 開頭，並包含 `## 衣櫃概況`、衣服種類區段、`## 搭配組合`、`## 推導與備註`。
- 衣服種類至少包括上衣、下身、洋裝、外套、內衣、內褲、襪類、睡衣、家居服、制服、工作服、運動服、泳裝、鞋類、包包與配件。
- 每個種類使用 Markdown table，固定包含「款式」「顏色」「材質」「數量」「主要場合」「狀態」「備註」七欄；可再加上季節、價格級距或保養方式。
- 顏色與材質必須分開描述；狀態要說明實際持有情況（例如常穿、良好、備用、季節收納、待修補），備註要交代替換、保養、收納或搭配理由，不能留成空泛短句。
- 每個色款都要能獨立辨識：同一剪裁只要顏色不同，就必須分成不同列，不能使用「黑／白」或「多色」合併；只有款式、顏色、材質、版型、用途與狀態都相同時才可合併數量。
- 每一列都要具體描述版型或結構、單一色款、材質組成或觸感、主要場合、目前持有狀態，以及可執行的替換、保養、收納或搭配備註，避免空泛的「可搭配多種衣物」。
- 「總件數」必須等於所有清單數量的加總。數量應反映角色的生活與經濟條件，並能支援重複搭配。
- 內衣、內褲、襪類與睡衣依一般衣物處理，納入總數與場合完整性。
- 搭配組合只能使用清單中已存在的款式。

## Reasoning rules

- 先保留明確設定，再推導生活必需品，最後補足可搭配的創作內容。
- 經濟普通不等於衣物貧乏；應保留耐穿日常品、少量重點單品與合理替換量。
- 內容不足時採用可恢復的常識預設並在備註標示；不要因缺少單一細節停住整個流程。
- 不把推導當成來源事實，也不覆寫 Blueprint 或其他模式模組。

## Output

提交一份完整 wardrobe Markdown proposal。完成後以簡短摘要說明數量邏輯、主要風格與仍可調整的假設。
