# 跨模式 Wardrobe 正式產物設計

## 狀態

- 設計狀態：已取得使用者確認
- 日期：2026-08-09
- 範圍：ST-workspace-v3

## 1. 目標

建立一個跨珠璣模式與調色盤模式共用的 `wardrobe` 正式產物。它不是角色設定的備註，也不是只供 Agent 參考的中間資料，而是會通過驗證、可獨立修訂，並直接編譯進最終角色卡的完整衣櫃內容。

主要目標：

1. 角色設定完成後，系統預設自動產生衣櫃；使用者可用自然語言停用或延後。
2. 產物以容易閱讀與手動修改的 Markdown 為主要內容。
3. 依衣服種類與色款列出衣櫃；只有完全相同的款式、顏色與主要特徵才能合併，顏色不同即使剪裁相同也必須分列。
4. 支援完整衣物範圍，包括內衣、內褲、襪類、睡衣、家居服、制服、運動服、泳裝、鞋類、包包與配件。
5. Agent 根據 Blueprint、既有角色模組、性格、生活方式、經濟狀況、世界設定與已接受事實推導合理數量與搭配。
6. 修改衣櫃時建立新 revision，不重跑訪談、不重建角色設定，也不覆蓋已發布版本。

## 2. 不在本次範圍

- 不修改珠璣七模組或調色盤四模組的既有欄位與順序。
- 不要求使用者填寫衣櫃數量、預算或底層 schema 參數。
- 不為珠璣與調色盤建立兩套不同的衣櫃格式。
- 本次不新增獨立 Wardrobe Critic agent；由引擎驗證與既有 Character Critic 共同完成檢查。
- 不把衣櫃內容直接寫入既有 appearance 模組，避免衣櫃與外貌設定耦合。

## 3. 方案與決策

曾考量三種方案：

1. 將衣櫃放入既有 appearance：改動少，但無法方便地單獨修訂。
2. 珠璣與調色盤各自建立衣櫃模組：模式特色明確，但會造成重複格式與跨模式不一致。
3. 建立獨立跨模式 `wardrobe` artifact：可共用、可獨立審查與編譯，並可延後擴充。

採用方案 3。Wardrobe 是每個角色一份、與模式無關的正式內容。

## 4. 生命週期與資料流

```text
訪談
  -> Blueprint confirmed
  -> 珠璣／調色盤角色設定完成
  -> Director 預設建立 Wardrobe 任務
  -> Wardrobe Creator 產生 wardrobe.md
  -> 引擎解析、驗證與保存 revision
  -> Character Critic 檢查設定一致性
  -> 編譯 canonical character payload
  -> 發布 JSON／PNG 卡片
```

Wardrobe 任務的輸入為：

- 已確認 Blueprint 的角色方向。
- 珠璣或調色盤已完成的角色模組。
- 世界設定與已接受的事實（若有）。
- 既有 wardrobe revision（修訂時）。

Wardrobe 任務的輸出為角色專案內的 `characters/<character-folder>/wardrobe/wardrobe.md`。每次正式修改都建立 revision，工作區始終保留最新有效版本與歷史版本。

預設情況下，完成角色設定後自動生成。使用者可以透過自然語言表示「先不要衣櫃」、「之後再做」或「不要建立衣櫃」，Director 便跳過或延後；不增加專門的問卷參數。

## 5. Markdown 內容規格

`wardrobe.md` 是人類可讀的主要內容與編輯入口。固定標題只用於協助解析，不要求使用者理解底層資料模型。

必要區段：

1. `# <角色> 的衣櫃`
2. `## 衣櫃概況`
3. 各衣服種類的 `##` 區段
4. `## 搭配組合`
5. `## 推導與備註`

衣服種類至少包括：

- 上衣、下身、洋裝、外套
- 內衣、內褲、襪類
- 睡衣、家居服
- 制服、工作服、運動服、泳裝
- 鞋類、包包、配件

衣物清單使用 Markdown table。新建立或完整修訂的衣櫃，每個種類固定使用七個欄位：款式、顏色、材質、數量、主要場合、狀態、備註。只有款式、顏色、材質、版型、用途與狀態都相同的衣物可以合併為一項；同款不同顏色必須分列，不能用「黑／白」或「多色」把不同持有物合併。每項必須包含：

- 款式名稱
- 顏色
- 材質
- 實際數量
- 主要使用場合
- 目前持有狀態
- 針對替換、保養、收納或搭配的備註

可選欄位包括季節、購買方式與價格級距。舊 revision 可以保留較少欄位以維持相容性，但 Wardrobe Creator 產生的新內容不得省略上述七欄。

衣櫃概況必須標示總件數。引擎以所有衣物項目的數量加總核對總件數。例如總件數為 200 時，可以用相同色款的多件數量合併描述，但不同顏色必須各自列出，加總結果必須為 200。

搭配組合引用衣物款式名稱，不直接複製衣物內容；解析器會拒絕不存在的引用，或在可安全推斷時由 Agent 修復。

## 6. 推導規則

Wardrobe Creator 必須依下列優先順序推導：

1. 明確角色設定與已接受事實。
2. 世界設定、氣候、季節、職業與生活場所。
3. 角色性格、審美、社交需求與日常作息。
4. 經濟狀況、購物習慣、洗衣頻率與可用收納空間。
5. 合理的創作補完。

推導結果需要兼顧：

- 日常替換所需的數量。
- 可重複搭配，而非每件只能穿一次。
- 平價日常單品與少量重點單品的比例。
- 季節、場合與生活活動的覆蓋。
- 既有外貌與角色性格的一致性。

明確設定、合理推導與自由補完要在 `推導與備註` 區分開記錄。資料不足時採用可恢復預設，不因單一缺值阻斷流程。

## 7. Agent 與技能

新增：

- `wardrobe-creator` agent
- `wardrobe-creation` skill
- 對應的 personality 檔案，確保行為風格與其他專用 Agent 一樣有明確掛載來源。

Wardrobe Creator 負責產生與局部修訂 Markdown；不負責修改 Blueprint 或珠璣／調色盤模組。Director 負責任務路由與發布 gate。既有 Character Critic 負責檢查角色一致性；引擎負責結構、數量與引用驗證。

## 8. Artifact、revision 與編輯

`wardrobe` 必須成為正式 artifact kind，具有角色識別、來源模式、目前 revision、審查狀態與內容檔案位置。內容檔案固定位於角色專案資料夾的 `characters/<character-folder>/wardrobe/wardrobe.md`，歷史版本位於同一角色資料夾的 `wardrobe/revisions/`。

使用者可直接提出自然語言修改，例如「增加兩件冬季外套」或「把整體改得更符合普通家庭」。Agent 只更新受影響的衣服種類與搭配，然後重新檢查總件數與引用。若修改無法安全套用，保留上一個有效 revision。

## 9. 編譯與最終卡片

Canonical character payload 新增正式 `wardrobe` 欄位，保留完整 Markdown 內容與必要的解析結果。支援結構化欄位的卡片格式直接使用完整衣櫃；舊格式則使用受控文字 fallback，但不丟失原始 Markdown。

編譯必須確保：

- 珠璣與調色盤都能讀取相同的 wardrobe 內容。
- wardrobe revision 與發布版本一致。
- 重新發布時使用最新有效 revision。
- 未通過驗證的草稿不會進入正式卡片。

專案輸出結構：

```text
project/
├─ blueprint/
├─ characters/
│  └─ <character-folder>/
│     ├─ character.json
│     ├─ zhuji/
│     ├─ palette/
│     └─ wardrobe/
│        ├─ wardrobe.md
│        └─ revisions/
└─ output/
```

## 10. 錯誤處理

- Markdown 缺少可推導欄位：Agent 自動補完並標記假設。
- 數量格式錯誤：自動修復；無法判斷時保留上次有效版本。
- 總件數不一致：先嘗試調整可推導項目，仍不一致才提出一個簡短問題。
- 搭配引用不存在：自動改用最接近的既有款式或移除無效搭配，並記錄修訂。
- 與角色設定矛盾：Character Critic 建立可修訂問題，不破壞既有版本。
- 編譯失敗：阻止該 revision 發布，但保留已發布版本與工作區檔案。

任何錯誤都不得清空既有 wardrobe 或使整個角色專案回到未完成狀態。

## 11. 驗證與測試

必須新增：

1. Markdown parser 的標題、table、數量與總件數測試。
2. 相同色款合併、同款不同顏色與其他變體分列的測試。
3. 內衣、內褲、襪類、睡衣等完整分類測試。
4. 200 件衣物的總數核對測試。
5. 珠璣與調色盤共用 wardrobe 的整合測試。
6. 自然語言局部修改與 revision 保留測試。
7. Character Critic 一致性檢查測試。
8. 編譯後 JSON／PNG 內含完整 wardrobe 的測試。
9. 失敗修復、舊 revision 保留與發布 gate 的回歸測試。

## 12. 完成條件

本設計完成實作後，以下條件必須全部成立：

- 角色設定完成後預設能產生 `wardrobe.md`。
- 珠璣與調色盤不需要各自維護衣櫃格式。
- 衣物能按種類與完全相同的色款合併，數量可核對；同款不同顏色會分列。
- 衣櫃可包含完整私人服裝分類。
- 使用者能以自然語言單獨修改衣櫃。
- 修改後能產生新 revision 並重新發布。
- 最終角色卡可直接使用 wardrobe 內容。
- 任何失敗都不會破壞上一個有效版本。
